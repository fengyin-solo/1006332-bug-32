# 廊内能耗计量：流水线与口径决策

这一篇把能耗计量从「本地能跑、线上对不上」固化成一条流水线，所有取舍都写在这里，
改动前先读这一篇。实现集中在 `frontend/src/data/energy.ts`，页面只负责展示。

## 一条流水线

- 依赖版本只认 `frontend/package-lock.json`，装依赖一律 `npm ci`，本地、容器、线上同一份锁文件。
- 本地与容器同一条链路：`npm ci` → `npm run build` → `npm run serve`
  （`vite preview`，端口 5173）。`Makefile` 的 `make start` 与 `frontend/Dockerfile` 是同一串命令。
- 环境之间的差异只留在配置里：`.env.development` / `.env.production` / `.env.example`，
  目前只有 `VITE_APP_NAME`、`VITE_API_BASE`、`VITE_APP_TZ` 三项，代码里不写死环境值。
- 时区统一走 `src/data/time.ts`：「今天」按 `VITE_APP_TZ`（默认 `Asia/Shanghai`）换算，
  统计周期、抄表日期的比较全是字符串日期运算，不经过本机时区，两个环境算出来必然一致。
- 自检是流水线的一环：`make selfcheck` = `npm ci` + 类型检查 + 生产构建 + `npm run selfcheck`
  （能耗数据自检，与页面共用同一份逻辑）。

## 数据口径（谁优先、怎么统一，都在这里定）

1. **既有台账照原编号搬过来**，按抄表日期升序落位，不重新编号。
2. **早年只有用电量、没有用水量的，用水量按 0 m³ 补录**，自检另起一行说明；
   原值（空）不丢，缘由留在自检报告里作对照。早年没登记的点位不虚构记录，同样另起一行说明。
3. **重复录入只认第一次**（同编号按抄表日期最早的那份），后到的整条退回、条数不叠加，
   退回那份的取值只留在自检报告里作对照。
4. **统计周期与抄表日期互相矛盾的记录保留在台账里**，状态置「数据异常」，自检列明缘由。
   抄表窗口定为：周期当月 + 次月前 5 天（`READING_GRACE_DAYS`）。
5. **计量数据落库前先校验**：必填项齐全、用电量/用水量为非负数值、统计周期格式 `YYYY-MM`、
   抄表日期不晚于应用时区下的今天、抄表日期落在抄表窗口内，任一不过就整条拒收。
6. **权限**：记录登记权属单位与责任岗位，跨单位/跨岗位看到的只读，越权提交一律拒绝；
   改动的记录仍归原岗位，权属字段不随操作人变。能耗计量归「管廊运营中心·能耗计量岗」，
   值班台账归「管廊运营中心·运维值班岗」，示例数据里 `ENER-0003` 归「自来水公司·供水计量岗」，
   用来演示外单位只读。
7. **对账**：对账待办 = 待抄表 + 数据异常，结论文字由 `energyReconSummary` 生成，
   值班台账 `DUTY-0001` 的交接事项与对账面板用的是同一段文字，条数天然对得上；
   页面上同时显示两边数字，不一致会红字提示。

## 自检清单（页面与 `npm run selfcheck` 同源）

- 数据依赖缺失：必填字段缺失（含早年未登记项），逐条注明补录口径。
- 计量编号冲突：重复录入只留第一次，退回那份的对照值写进缘由。
- 周期矛盾：统计周期与抄表日期互相矛盾的记录，注明窗口口径。
- 自检结果条数 = 页面「自检结果」列表条数，两边是同一份数据。

当前种子数据的自检结果为 6 条：1 条计量编号冲突（LS-2024-005 重复录入）、
4 条数据依赖缺失（LS-2023-001、LS-2023-002 缺用水量，LS-2024-004 缺抄表人员，
天然气舱调压站 2023 年未登记）、1 条周期矛盾（LS-2024-005）。
